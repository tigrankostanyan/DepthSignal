# Tabletop Exercise — QuantScreen

## 1. Purpose
To prepare the team for a real security incident by simulating a scenario and evaluating the response.

## 2. Frequency
Twice a year (e.g., March, September).

## 3. Participants
- Security Lead (facilitator)
- Backend Lead
- DevOps Lead
- Compliance Officer
- PR/Communications (if needed)
- Any other stakeholders

## 4. Sample Scenario: Data Breach
**Scenario:** An attacker exploited a vulnerability in the payment API and accessed user email addresses and hashed passwords.

### Phase 1: Detection (10 min)
- **Prompt:** You receive an alert from the SIEM about unusual database queries.
- **Question:** How would you confirm the breach? What logs would you check?

### Phase 2: Containment (15 min)
- **Prompt:** You have confirmed the breach.
- **Question:** What steps would you take to contain the breach? How would you isolate the affected systems?

### Phase 3: Eradication (15 min)
- **Prompt:** The attacker is still active.
- **Question:** How would you revoke access? How would you patch the vulnerability?

### Phase 4: Recovery (15 min)
- **Prompt:** The incident is contained.
- **Question:** How would you restore services? What would you communicate to users?

### Phase 5: Post-Mortem (15 min)
- **Prompt:** The incident is over.
- **Question:** What would you include in the post-mortem report? What changes would you make to prevent recurrence?

## 5. Evaluation Criteria
- Speed of detection
- Clarity of communication
- Effectiveness of containment
- Completeness of recovery
- Quality of post-mortem

## 6. Outcome
- Document lessons learned
- Update incident response plan
- Assign action items
